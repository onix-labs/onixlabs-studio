# ONIXLabs Studio 2026.1.0-beta.6 — what changed

**Range:** `v2026.1.0-beta.5..main` (`d9b228fc`)
**Span:** 2026-09-15 → 2026-10-17
**Commits:** 137 total, 137 excluding merges

---

## Summary

Six themes dominate this beta.

A security and performance audit closes the range. Studio asks whether you trust a repository
before version control runs in its folder; Codex asks through Studio's own permission card before a
command runs or a file changes; permission cards say what they are asking about; a markdown file's
raw HTML is sanitised; a plugin process gets an allow-listed environment rather than the user's
whole shell; clone credentials are never written down; write confinement follows symbolic links;
and the AI Manager's agent asks before writing a profile or a skill. On the performance side, a cold
start no longer waits on the login shell's profile, the System Monitor reads at a rate you choose,
the Containers view reads stats one at a time and reloads once per burst of events, and both views
pause their feeds while the window is off screen.

More of the back end leaves core for plugin processes. Git speaks a version-control protocol from a
plugin of its own; code hosting is a seam, with GitHub behind it; and Docker and Podman run as
container-engine plugins, so core no longer speaks the Docker Engine API. The Repository panel
takes in worktrees, gains menus on its sections, a history strip, and issue actions from an issue's
document.

Agents arrive in the tool views, one per view and kept to it. The System Monitor, the AI Manager,
the Plugin Manager and the Containers view each dock a focused agent with that view's tools and
nothing else. The AI Model Manager becomes the AI Manager, holding local models, prompt profiles
and skills; the tool views share one layout of side panel, table and strips.

Notifications reach the operating system's notification centre while Studio is in the background,
and the in-app stack recedes, stacks the way you choose and mutes from its tray.

The Welcome screen becomes a front door of four tabs: browse and clone your repositories, flat or
as a worktree; Create Something is a project wizard that briefs an agent; and the setup wizard
offers plugins first.

The workspace and editors gain real strips everywhere, a find & replace panel, in-place rename and
create, an image viewer, Monaco-edited API bodies, floating scroll bars and a CMake target tree.

Windows and Linux get window chrome of their own. Windows keeps the system's caption buttons over
Studio's strip, and Linux windows lose their frame for controls Studio draws itself.

**Upgrade note:** opening a folder that holds a repository now asks "Do you trust this repository?"
before Git runs in it, once per repository. **Don't trust** is the first button and what closing
the window means; a declined repository shows a restricted state in the Repository and Commit
panels with a way back in. Every repository is asked, a clone or a project Studio just created
included; the answer is remembered per folder.

**Upgrade note:** a version-control, hosting, container-engine or decoder plugin no longer inherits
every variable your shell exports. It gets `PATH`, the home folder, locale, a temporary folder, the
SSH agent, proxy settings and the families its own tools read (`GIT_*`, `DOCKER_*`, `CONTAINER_*`,
`CODEX_*`, `XDG_*`). If `git` or `gh` under Studio relied on another export, set it in a Git
config or the tool's own configuration instead. Agent harnesses are unchanged: an agent runs in
your shell by design.

**Upgrade note:** four plugins were re-released to carry these fixes — Codex 0.7.0 (asks through
the permission card and now drives `codex app-server`), Claude 0.14.0 (symlink-safe confinement and
the command-line block), Docker 30.2.0 and Podman 7.2.0 (the one-shot stats read). The Plugin
Manager offers each as a waiting update; take them, since the fixes above need both halves.
